# 本规范的维护协议（供 AI 读取）

本套「开发环境纪律」由 `~/.aiglobal` 自己管理，**不再依赖 rulesync**。唯一源文件在：
- 规则：`~/.aiglobal/rules/`
- 技能：`~/.aiglobal/skills/`

## 改规则的流程
1. 编辑 `~/.aiglobal/rules/` 下对应的 `.md`（新规则可新建文件，文件名前缀数字控制加载顺序）
2. 运行 `airules`（等价于 `bash ~/.aiglobal/scripts/sync.sh`）重新分发到所有 agent
3. 用 `bash ~/.aiglobal/scripts/sync.sh --check` 确认无漂移（分发内置自检：缺界面设计门规则会直接报错退出）
4. **不要手改生成产物**（见下表）

## 分发产物一览
| 产物 | 生成方式 | 谁读 |
|---|---|---|
| `~/.claude/CLAUDE.md` | magpie Library | Claude Code |
| `~/.config/opencode/AGENTS.md` | magpie Library | opencode |
| `~/.copilot/copilot-instructions.md` | magpie Library | Copilot CLI |
| `~/.trae-cn/user_rules/rule-aiglobal.md` | `sync.sh` 聚合直写 | **Trae CN（用户级规则）** |
| `<agent>/skills/<名>`（软链） | `sync.sh` | Claude / OpenCode / Copilot / Trae CN |

> **为什么 Trae CN 要单独写**：magpie 不支持 Trae CN（源码 `internal/library/targets.go` 里没有该目标），
> 且 Trae CN 只读 `~/.trae-cn/user_rules/` 下的单个 `.md`，所以要由 `sync.sh` 聚合后直接写入。

> **为什么技能用软链而不是交给 magpie**：magpie 的技能只能从 GitHub 拉取或在 App 的 Library 页添加，
> 本地目录没有 CLI 入口。软链让 4 个 agent 读同一份 git 版本化源，避免内容漂移。

## 新增 agent 时
1. 若 magpie 支持：在 `scripts/sync.sh` 的 `MAGPIE_AGENTS` 里加上该 agent 名
2. 若 magpie 不支持（如 Trae CN）：在 `scripts/sync.sh` 里补一段直写逻辑
3. 技能软链：在 `link_skills` 调用列表里加一行
4. 用 `--check` 验证，再提交

## 唯一源 / 分发层 的边界
- `~/.aiglobal` 是**内容真源**（git 版本化，可 diff、可回滚）
- magpie 是**分发通道**（把内容按各 agent 格式写进去，只回收自己写的部分）
- 两者不可同时写同一个文件：magpie 用 marker block 插入，脚本是整体覆写
