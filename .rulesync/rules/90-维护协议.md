# 本规范的维护协议（供 AI 读取）

本套「开发环境纪律」由 **rulesync** 管理，唯一源文件在：
- 规则：`~/.aiglobal/.rulesync/rules/`
- 技能：`~/.aiglobal/.rulesync/skills/`

## 改规则的流程
1. 编辑 `~/.aiglobal/.rulesync/rules/` 下对应的 `.md`（新规则可新建文件，文件名前缀数字控制加载顺序）
2. 运行 `airules`（等价于 `bash ~/.aiglobal/scripts/sync-trae-cn.sh`）重新分发到所有 agent
3. 用 `cd ~/.aiglobal && rulesync generate --check` 确认无漂移（`airules` 内置分发自检：缺界面设计门规则会直接报错退出）
4. **不要手改生成产物**（见下表）

## 分发产物一览
| 产物 | 生成方式 | 谁读 |
|---|---|---|
| `~/.config/opencode/AGENTS.md` | rulesync | opencode |
| `~/.claude/CLAUDE.md` | rulesync | Claude Code |
| `~/.trae-cn/user_rules/rule-aiglobal.md` | 桥接脚本聚合 | **Trae CN（用户级规则）** |
| `~/.trae-cn/skills/<名>`（软链） | 桥接脚本 | Trae CN（用户级技能） |
| `<项目>/.trae/rules/*.md` | rulesync（项目级） | Trae / Trae CN |

> **为什么需要桥接脚本**：rulesync 对 Trae 只支持项目级 `.trae/rules/`，**不支持 Trae 用户级规则**；
> 且它写的是国际版路径 `~/.trae/`，而 Trae CN 读 `~/.trae-cn/`。
> 因此由 `~/.aiglobal/scripts/sync-trae-cn.sh` 把规则聚合后写入 `~/.trae-cn/user_rules/`，并把技能软链过去。
> Trae CN 改动后需重载窗口才会读到新规则。

## 新增 agent 时
1. 在 `~/.aiglobal/rulesync.jsonc` 的 `targets` 里加上该 agent 名，重跑 `airules`
2. 若该 agent 的用户级规则路径 rulesync 不支持，则在 `scripts/sync-trae-cn.sh` 里补一段桥接

即：用户只需说需求，AI 负责改源文件 + 分发；用户无需手动维护。
