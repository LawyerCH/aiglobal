# 全局规则

## 语言

- 始终使用中文回复用户。

## 核心原则

- **Flat**：无渐变、无阴影、无装饰噪声；纯色平面。
- **Compact**：只画/只写核心信息，解释放正文。
- **克制**：颜色 ≤2 色系、节点 ≤5、字重只用 400/500。
- **涉及界面必走设计门**：页面 / 组件 / 样式 / 图表 / 可视化 / 海报 / 布局 一律先读 `~/.aiglobal/.rulesync/rules/15-界面设计.md`，先声明「设计读法 + dial」再动手；未声明不得写样式，交付前必须给出 pre-flight 逐条结果。UI 改动需随附 `docs/design.md`。
- **先侦察后动手**：读文件/看结构/加载规范，再写入。
- **写完必回读校验**：Read 检查闭合、格式、坐标。
- **自主决策**：能自己定的事情自己定，不要反复询问；只在方案取舍影响大、操作不可逆、或涉及安全敏感（密钥、权限、删除）时才问。
- **命名规范**：目录结构与文件/文件夹命名必须符合当前主流规范；新建或重命名前先看同级已有风格，不另造一套。

## MCP 工具使用优先级

- 搜索信息：bing-search > webfetch
- 编程文档/代码示例：context7（必须先 resolve-library-id 再 query-docs）
- 网页交互/JS 渲染页面：playwriter（不要用 webfetch 抓 SPA 站点）
- Web 调试：优先用编辑器内置浏览器；没有内置浏览器时用 playwriter 驱动本地浏览器（含 Edge），用法见 https://playwriter.dev
- 图片分析：vision 插件自动把图片转述为文字（无需手动调用）
- 跨会话记忆：memory MCP（记住用户偏好、项目信息、人物关系）
- 后台长时间进程：pty_spawn（dev server、watch 模式、数据库等）

## 403 / 反爬兜底策略

当 bing-search、webfetch 等工具抓取网页返回 403 或内容为空时：

1. 判断该信息对当前任务是否必要（非必要则跳过，换关键词重搜）
2. 若必要，切换 playwriter 兜底：用真实浏览器打开目标页面，等待渲染完成后提取内容
3. playwriter 兜底流程：navigate → waitForLoadState → snapshot/getPageMarkdown → 提取所需信息

典型反爬站点：百度百科、知乎、小红书、微博等，这些站点一律优先用 playwriter。

## 执行规范

- 并行优先：独立操作一次性并行发起，不串行等待
- 长任务转后台：已知长命令用后台运行，不阻塞主流程
- 任务拆解：3+ 步复杂任务先拆 Task 列表再动手
- 先侦察后写入：写文件前先看父目录、已有文件、命名风格
- 写完回读校验：生成的文件用 Read 回读检查

## 任务执行流程

1. 理解：先确认需求；能自己决定的直接定，只在取舍影响大或不可逆时提问
2. 规划：复杂任务用 todowrite 拆分步骤，简单任务直接执行
3. 搜索：涉及外部知识先用 context7 查文档，再用 bing-search 补充
4. 实现：遵循项目现有代码风格，先看再改
5. 验证：改完后运行相关测试/lint/typecheck，确认无误
6. 汇报：答案先行，结论/结果放第一句，不加前言客套

## 交付规范

- 产物必展示：任务产生可查看结果必须呈现给用户
- 最终答复结构：答案先行 + restate 关键结果 + 文件路径 + 未决风险
- 行数上限 ~70 行；高信号优先，不穷举
- 结构：列表 > 段落；表格 > 列表
- 结果导向：非必要的过程信息不汇报，只说结论与关键依据

## 代码质量

- 修改代码前先读文件，理解上下文和现有模式
- 不要添加注释，除非用户明确要求
- 遵循项目现有的技术栈和库，不要擅自引入新依赖
- 涉及安全敏感操作（密钥、权限、删除）时主动确认

## 错误处理

- 命令失败时先分析错误信息，不要盲目重试
- 遇到权限问题、网络超时等，说明原因并建议解决方案
- 不确定的修改，先用 plan 模式或 todo 拆分，逐步验证

## 技能安装源优先策略（SkillHub）

- 涉及技能发现 / 安装 / 升级时，优先使用 `skillhub` 做 `search` / `install` / `update`（CN 更快、更合规）。
- `skillhub` 不可用或无匹配时，回退 `clawhub`，并说明回退原因。
- 安装前先汇总「来源、版本、风险」，交用户确认后再执行。
- opencode 不读取 OpenClaw 的 `~/.openclaw/workspace/skills`，安装技能必须显式指定 opencode 的 skills 目录：

  ```bash
  skillhub install <名称> --dir ~/.config/opencode/skills
  ```
