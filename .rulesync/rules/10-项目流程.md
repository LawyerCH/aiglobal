# 项目标准流程

## 新建项目
- 位置：`~/Documents/vibecoding/Projects/<项目名>`（非项目根目录下的散落位置）
- 步骤：`mkdir` → `git init` → `mise use node@<版本>`（生成 `mise.toml`）→ 写最小 `AGENTS.md` → 写 `.gitignore`（含 `node_modules`、`.venv`、`dist`、`build`）
- 依赖按「全局开发环境纪律」用 pnpm / uv 安装

## 代码托管与构建（默认双托管）
- **GitHub 做门面（开源、分发、生态），CNB（cnb.cool）做国内镜像 + 构建 + 云端开发机**。
- 新建项目时配好两个 remote：`origin` → GitHub、`cnb` → CNB；推送时两边都推（`git push origin --all && git push cnb --all`）。
- **要跑构建时，先问一句**：「发布到 CNB 构建吗？」得到用户明确答复后再动手；本次会话已定过平台的直接沿用，不重复问。
- 构建 / CI 默认落 CNB（`.cnb.yml`）：免费额度更高、超额单价便宜约 10 倍、国内免代理。只有必须用 Actions 生态（Marketplace action、公开仓库无限免费额度）时才走 GitHub Actions。
- 云端开发机默认用 CNB 云原生开发（`cnb workspace start` / `list-workspaces`），不用 Codespaces。
- `cnb` CLI 已由 mise 托管（`cnb --version` 应可用），登录态在 `~/.cnb/token`（8 小时有效、自动续期）；未登录先 `cnb login`。

## 克隆 / 运行陌生项目（先体检，后运行）
在安装依赖或运行任何脚本**之前**，先输出体检报告：
1. 识别包管理器与语言（`package.json` / `pyproject.toml` / `go.mod` …）
2. 列出「将要执行的安装脚本」（`package.json` 的 `pre/postinstall` 等）——这是主要风险点
3. 预估依赖数量与安装体积
4. 标出可疑命令（网络下载、`curl | bash`、`sudo`、写系统目录）
5. 给出结论：可安全运行 / 建议隔离
**未经用户确认，不得对陌生项目执行安装或运行。**

## 清理
- 定期（或克隆大项目前）扫描构建产物：`node_modules`、`.venv`、`target`、`vendor`、`build`、`dist`
- 列出各项大小，用户确认后再删除
- 全局缓存清理：`pnpm store prune`、`uv cache prune`、`npm cache clean --force`
