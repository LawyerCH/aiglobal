# 配置与语言规范

> 借鉴 **12-Factor App**（配置 / 依赖）与 **Google 语言风格指南**。

## 配置（12-Factor III）
- **配置与代码严格分离**：会随环境变化的值（数据库地址、外部服务凭据、密钥）一律走**环境变量**，不写死在代码里
- 判断标准：**代码库能否随时开源而不泄露任何凭据**？不能 → 说明有配置写死在了代码里
- 不用「按环境名分组」（dev/staging/prod 各一份配置）的写法；改为**每个变量独立**管理
- `.env` 必须进 `.gitignore`；本机密钥优先存系统钥匙串（参见本机 secrets 做法）

## 依赖（12-Factor II）
- **显式声明 + 隔离**：所有依赖写进清单（`package.json` / `pyproject.toml`），并在**项目内隔离执行**（`node_modules` / `.venv`），**不依赖系统全局包**
- 新协作者应能只装「运行时 + 包管理器」，用一条构建命令就绪
- 不隐式依赖系统工具；需要则显式声明

## 语言风格（项目配置优先）
- **项目已有 lint / format 配置（prettier / eslint / ruff / black）时，一律以项目配置为准**，不要强加个人风格
- 无配置时的默认：提交前用项目内 formatter 跑一遍
- Python 要点：公共 API 加**类型注解**；**不用可变对象作默认参数**（用 `None` + 函数内初始化）；不写裸 `except:`；少用 `staticmethod`
- 可读性优先于简短，不为省行数牺牲清晰度
