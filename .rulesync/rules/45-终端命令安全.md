# 终端命令安全（防无人值守卡死）

对 AI agent 而言，任意一条 shell 命令都可能因为「等待人类输入」而无限挂起，表现为对话长时间无响应。
本规则约束**所有** agent 的命令调用方式，优先级等同于环境纪律。

## 硬规则

| # | 规则 | 原因 |
|---|---|---|
| 1 | 命令末尾统一加 `</dev/null` | 任何交互式提示立即收到 EOF，而不是等按键 |
| 2 | 网络 / 安装 / 构建类命令套 `safe <秒> <命令>` | `safe` 是 `~/.local/bin/safe`，超时自动终止（退出码 142） |
| 3 | 禁止调用交互式程序 | `vim/vi/nano/less/more/man/sudo/su/ssh`（无 `BatchMode=yes`）、裸 `python`/`node`/`irb`、`npm login`、`gh auth login`、`git commit`（无 `-m`）、`git rebase -i` |
| 4 | 绕过可能吞 stdin 的别名 | 用 `command cat`、`command grep`、`command ls` 或绝对路径 |
| 5 | 不用 `zsh -ic` | 会重新加载用户配置并继承交互行为；必须用时加 `</dev/null` 并套 `safe` |
| 6 | 分页器一律禁用 | 命令前加 `PAGER=cat GIT_PAGER=cat GH_PAGER=cat`，或给 git 加 `--no-pager` |
| 7 | 卡住即终止，不连续重试 | 60s 无输出就放弃，改非交互写法；同一思路最多重试 1 次，第二次前先查原因 |

## 发命令前的自检（四问）

1. 有没有 `</dev/null`？
2. 会不会打开分页器或编辑器？
3. 会不会弹密码 / 确认 / 选择提示？
4. 超过 60s 没结束怎么办？

四问有任何一条答不上，先把命令改成非交互写法再发。

## 已知坑（实测）

- `alias cat='bat ... || cat'` 这类「命令 + 回退」别名：zsh 把参数追加到别名串末尾，前半段变成**裸命令读 stdin**，永久阻塞。已在 `~/.zshrc` 改为函数。
- `PAGER=less` 时 `git log` / `gh pr view` / `man` 会停在分页器等按键。已在 `~/.zshrc` 把各分页器统一设为 `cat`。
- 宿主注入的 `GIT_PAGER=cat`、`GIT_EDITOR=:` 不可依赖，各 agent 自己保证。
