# 界面设计硬规则（触发式）

> 这条规则不是风格偏好，是**执行门槛**。任何界面工作，没走完三道门就算没做完。

## 一、触发条件

出现以下任一情况即触发，**包括修改现有界面**：

- 新建或修改页面、组件、布局、样式表
- 做仪表盘、数据表、可视化图表、报告页
- 做海报、banner、封面、幻灯片、分享图
- 调整间距、字号、配色、圆角等视觉细节
- 用 HTML/CSS/SVG 输出任何给人看的东西

**不触发**：纯后端接口、纯脚本、CLI 的纯文本输出。CLI 的交互式 TUI 算界面。

## 二、三道门

### 门 1：先声明设计读法（写代码之前）

必须在动手前输出**一行**，并在其中给出三个 dial 值：

> 设计读法：为 `<谁>` 做 `<什么界面>`，语气 `<克制/活泼/编辑感/仪器感>`，倾向 `<技术路线>`。
> dial：VARIANCE `<1-10>` / MOTION `<1-10>` / DENSITY `<1-10>`

dial 取值参考：

| 场景 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 内部工具 / 数据台 / 仪表盘 | 2-4 | 1-3 | 6-8 |
| 营销页 / 落地页 | 7-9 | 5-8 | 3-5 |
| 阅读优先（文档、长文、报告） | 3-5 | 1-3 | 2-4 |
| 政务 / 金融 / 合规类 | 2-3 | 1-2 | 4-5 |

未声明设计读法，**不得开始写样式**。

### 门 2：加载设计方法

按顺序尝试，第一个可用的就用：

1. `design-taste-frontend` skill（页面/落地页/重设计，含 pre-flight 清单）
2. `ui-ux-pro-max` skill（组件库、设计系统、配色与字体检索）
3. `frontend-ui-engineering` skill（可访问性、响应式、生产级界面）
4. 以上都不可用：按本文第四节清单逐条执行，并在回复里说明"skill 不可用，按内置清单执行"

### 门 3：交付前跑 pre-flight

在最终回复里**逐条**给出 PASS/FAIL，不许只写"已检查"。任何一条 FAIL 必须修完再交付。

## 三、交付物

UI 相关改动必须在项目内留下 `docs/design.md`（模板见第五节），并随改动一起提交。没有这份文件 = 未完成。

## 四、Pre-flight 清单（18 条）

| # | 检查项 | 判定标准 |
|---|---|---|
| 1 | 设计读法 | 已声明，含三个 dial 值 |
| 2 | 字号层级 | 至少 3 级（标题 / 正文 / 标注），不靠加粗硬撑 |
| 3 | 字重 | 只用 400 / 500；不用 600-900 |
| 4 | 行宽 | 正文 ≤ 72ch；超过就分栏或限宽 |
| 5 | 数字排版 | 表格与统计数字用等宽字体并右对齐 |
| 6 | 强调色 | 全站 ≤ 1 个强调色；语义色只用于状态（成功/警告/失败） |
| 7 | 对比度 | 正文 ≥ 4.5:1，≥18px 文字 ≥ 3:1；占位符同样适用 |
| 8 | 形状一致 | 圆角全站统一（0 / 2px / 8px 三选一），不混用 |
| 9 | 无阴影无渐变 | 层级只用 1px 线与留白表达 |
| 10 | 表格 | 表头吸顶、行高一致、hover 有反馈、列宽按内容分配 |
| 11 | 空状态 | 有，且说明"怎么产生第一条数据" |
| 12 | 加载态 | 骨架屏尺寸与最终布局一致，不用转圈图标糊弄 |
| 13 | 错误态 | 内联展示在出错位置，不用 `alert()` 或只在 console |
| 14 | 焦点态 | 键盘可达，focus ring 可见，不得裸写 `outline: none` |
| 15 | 双主题 | 浅色 + 深色（跟随系统），两种模式都实际看过 |
| 16 | 响应式 | < 768px 折叠为单栏；固定宽栅格必须说明折叠方式 |
| 17 | 文案 | 按钮文案单行不换行；同一意图全站只用一个措辞 |
| 18 | 设计文档 | `docs/design.md` 已写（读法 / dial / 关键决策 / 截图路径） |

## 六、个人默认色板（公文风）

用户未指定配色时，**默认用这套**，不要自创渐变色或蓝紫系：

| 角色 | 浅色主题 | 深色主题 | 用途 |
|---|---|---|---|
| 纸面 | `#FFFFFF` | `#141414` | 面板底色 |
| 背景 | `#F6F6F5` | `#0D0D0D` | 页面底色 |
| 墨色 | `#1A1A1A` | `#EDEDEB` | 正文、标题 |
| 次级墨 | `#5C5C5C` | `#A3A3A0` | 说明文字、表头 |
| 淡墨 | `#8A8A8A` | `#6E6E6B` | 占位符、禁用 |
| 分隔线 | `#E4E4E2` | `#2A2A28` | 1px 线，唯一层级手段 |
| 公文红 | `#B3261E` | `#E2574C` | 唯一强调色 |

规则：

- **只有两个色系**：灰阶 + 公文红。不引入绿、黄、蓝；状态用文字标签表达，不靠颜色单独承载信息。
- 公文红只出现在三处：① 当前选中/运行中的状态 ② 主按钮 ③ 页头那条 1px 红色分隔线。**不得用于大面积背景、正文、图表填充。**
- 红色文字必须 ≥ 4.5:1 对比度（`#B3261E` on `#FFFFFF` 约 5.9:1，可用；更浅的红不可用于正文）。
- 标题用衬线（`"Songti SC", "STSong", "SimSun", serif`），正文用系统无衬线，数字用等宽并 `font-variant-numeric: tabular-nums`。这是公文排版的固定搭配，不算"混用字体族"。
- 圆角统一 2px（或全 0），不要圆角按钮配直角卡片。

## 七、禁止项

- 未声明设计读法就写 CSS / 组件
- 紫色或靛蓝渐变光晕、发光按钮、玻璃拟态滥用
- 三等分等宽卡片堆成一行（"三个特性"式模板）
- 用 emoji 当图标（除非用户明确要求活泼风格）
- 大面积纯黑 `#000` / 纯白 `#fff`
- `outline: none` 且不提供替代焦点样式
- 用 `alert()` 充当错误提示
- 表格数字左对齐、不用等宽字体
- 在数据台里用营销大字、超大标题、夸张字距
- 只做浅色不做深色
- 交付时只说"已完成"，不给 pre-flight 结果

## 八、与"克制原则"的关系

overview 里的 Flat / Compact / 克制是**结果**，本文是**过程**。三者冲突时：

1. 本文的可访问性条款（对比度、焦点态、双主题）优先
2. 其次本文的形状与颜色一致条款
3. 最后才是紧凑程度：信息密度可以高，但不许用低对比度、小字号、贴边来换空间
