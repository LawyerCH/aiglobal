# 界面设计前置流程

这是**流程 skill**，不是风格库。界面工作先走流程，再谈审美。

## 何时用

- 新建页面、组件、布局、样式表
- 仪表盘、数据表、可视化、报告页
- 海报、banner、封面、幻灯片
- 调整间距/字号/配色/圆角等视觉细节
- 任何给人看的 HTML / CSS / SVG 产物

纯后端、纯脚本、CLI 纯文本输出不需要。CLI 的交互式 TUI 需要。

## 三步

### 1. 声明设计读法（动手前）

一行说清，并给三个 dial：

> 设计读法：为 `<谁>` 做 `<什么界面>`，语气 `<...>`，倾向 `<技术路线>`。
> dial：VARIANCE `<1-10>` / MOTION `<1-10>` / DENSITY `<1-10>`

| 场景 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 内部工具 / 数据台 | 2-4 | 1-3 | 6-8 |
| 营销页 / 落地页 | 7-9 | 5-8 | 3-5 |
| 阅读优先 | 3-5 | 1-3 | 2-4 |
| 政务 / 金融 / 合规 | 2-3 | 1-2 | 4-5 |

### 2. 选技术路线

- 已有项目：沿用现有组件、样式变量、命名，不引入第二套体系
- 新项目且无设计系统：原生 CSS 变量 + 系统字体，零依赖优先
- 需要现成设计系统：按官方包安装（Fluent / Carbon / Material / Radix / shadcn），**一个项目只用一套**，不要手抄它的样式再改 90%
- 字体：默认系统字体栈；不引外部字体 CDN；数字用等宽
- 图标：用图标库，不手写 SVG 路径，不拿 emoji 顶替

### 3. 交付前跑 pre-flight

逐条回复 PASS/FAIL，FAIL 必修。清单见下。

## Pre-flight 清单

| # | 检查项 | 判定标准 |
|---|---|---|
| 1 | 设计读法 | 已声明，含三个 dial |
| 2 | 字号层级 | 至少 3 级，不靠加粗硬撑 |
| 3 | 字重 | 只用 400 / 500 |
| 4 | 行宽 | 正文 ≤ 72ch |
| 5 | 数字排版 | 表格/统计数字等宽且右对齐 |
| 6 | 强调色 | 全站 ≤ 1 个；语义色仅表状态 |
| 7 | 对比度 | 正文 ≥ 4.5:1，大字 ≥ 3:1，占位符同样 |
| 8 | 形状一致 | 圆角全站统一（0 / 2px / 8px） |
| 9 | 无阴影无渐变 | 层级用 1px 线与留白 |
| 10 | 表格 | 表头吸顶、行高一致、hover 反馈、列宽按内容 |
| 11 | 空状态 | 有，且说明如何产生首条数据 |
| 12 | 加载态 | 骨架屏与最终布局同尺寸 |
| 13 | 错误态 | 内联展示，不用 `alert()` |
| 14 | 焦点态 | 键盘可达，focus ring 可见 |
| 15 | 双主题 | 浅色 + 深色，两种都实际看过 |
| 16 | 响应式 | < 768px 单栏，固定栅格有折叠说明 |
| 17 | 文案 | 按钮单行，同一意图只用一种措辞 |
| 18 | 设计文档 | `docs/design.md` 已写 |

## 默认色板（公文风）

用户未指定时用这套，不要自创蓝紫渐变：

| 角色 | 浅色 | 深色 |
|---|---|---|
| 纸面 | `#FFFFFF` | `#141414` |
| 背景 | `#F6F6F5` | `#0D0D0D` |
| 墨色 | `#1A1A1A` | `#EDEDEB` |
| 次级墨 | `#5C5C5C` | `#A3A3A0` |
| 分隔线 | `#E4E4E2` | `#2A2A28` |
| 公文红（唯一强调色） | `#B3261E` | `#E2574C` |

- 只有灰阶 + 红两个色系；状态用文字标签，不靠颜色单独承载信息
- 红只用于：选中/运行中、主按钮、页头 1px 分隔线；不做大面积背景
- 标题衬线（Songti SC / SimSun），正文系统无衬线，数字等宽 + `tabular-nums`
- 圆角统一 2px 或全 0

## 禁止项

- 没声明设计读法就写样式
- 紫/靛渐变光晕、发光按钮、玻璃拟态滥用
- 三等分等宽卡片堆一行
- emoji 当图标
- 大面积纯黑 `#000` / 纯白 `#fff`
- `outline: none` 无替代焦点
- `alert()` 当错误提示
- 表格数字左对齐、非等宽
- 数据台里用营销大字与夸张字距
- 只做浅色
- 交付时只说"已完成"

## 与"克制原则"冲突时

1. 可访问性（对比度、焦点、双主题）优先
2. 形状与颜色一致次之
3. 紧凑最后：密度可以高，但不许靠低对比度、小字号、贴边换空间
